Основы: что такое БД и как устроен Postgres

Раздел для тех, кто только подходит к базам данных или хочет навести порядок в терминах. У концептуальных карточек нет блока кода — они изучаются только через диалог с ИИ-ментором.

1. Что такое СУБД и зачем она

Зачем нужен Postgres вообще, и чем он отличается от файлов и других СУБД.

Зачем нам СУБД

Файлы умеют хранить байты. СУБД умеет хранить связанные данные надёжно, конкурентно и быстро.

СУБД отвечает сразу за пять задач, которые ты иначе делал бы руками: транзакционность, ссылочную целостность, изолированный конкурентный доступ, индексированный поиск и язык запросов. Каждая из этих задач по отдельности — это месяцы работы.

СУБД, база данных, кластер

Эти три слова часто путают. Запомни иерархию: процесс → кластер → база → подключение.

  • Процесс СУБД — программа postgres, запущенная на машине.
  • Кластер — каталог данных и инстанс, в котором лежит несколько БД.
  • База данных — изолированное пространство схем, таблиц, ролей, прав.
  • Сессия — конкретное подключение клиента к одной БД.
psql -h localhost -U postgres   -- подключение к кластеру
\l                              -- список БД в кластере
\c mydb                         -- переключиться в БД

О PostgreSQL

Open-source СУБД с почти 40-летней историей. Лицензия PostgreSQL — близка к BSD, разрешает почти всё.

Главные архитектурные особенности: MVCC без блокировок чтений, расширяемые типы и индексы, развитая поддержка JSON, оконных функций и CTE. По функциональности часто опережает коммерческих конкурентов.

Термины: настоящие и сленговые

tuple/row, relation/table, attribute/column, predicate, query plan — что значат эти слова.

В академических текстах и в документации Postgres ты встретишь оба варианта. Понимание словаря помогает читать pg_catalog, EXPLAIN и сообщения об ошибках без затыков.

2. Категории команд SQL

DDL, DML, DCL, TCL и зачем их различать.

DDL, DML, DCL, TCL

SQL делится на четыре категории по тому, что они делают.

-- DDL: структура
CREATE TABLE t (id int);
ALTER TABLE t ADD COLUMN name text;
DROP TABLE t;

-- DML: данные
INSERT INTO t VALUES (1, 'a');
SELECT * FROM t;
UPDATE t SET name = 'b' WHERE id = 1;
DELETE FROM t WHERE id = 1;

-- DCL: права
GRANT SELECT ON t TO readonly;
REVOKE SELECT ON t FROM readonly;

-- TCL: транзакции
BEGIN;
  UPDATE t SET name = 'c';
COMMIT;

Polezno: в Postgres DDL транзакционен — можно завернуть CREATE TABLE в BEGIN…ROLLBACK и откатить. В большинстве других СУБД это не работает.

SQL — декларативный язык

Ты описываешь, какой результат нужен. Как именно — решает планировщик.

Это и сила (компилятор/оптимизатор может выбрать быстрый план), и ловушка (один и тот же запрос может работать по-разному в зависимости от статистики, индексов и версии). Поэтому EXPLAIN — рабочий инструмент, а не «продвинутая опция».

Комментарии в SQL и в БД

Однострочные/многострочные в коде и постоянные через COMMENT ON.

-- однострочный
/* много-
   строчный */

COMMENT ON TABLE  users        IS 'учётные записи';
COMMENT ON COLUMN users.email  IS 'нормализованный e-mail (lowercase)';

-- посмотреть в psql:
\d+ users

3. Ключи и связи

PRIMARY KEY и FOREIGN KEY — основа реляционной модели.

Первичный и внешний ключи

PK однозначно идентифицирует строку, FK гарантирует ссылочную целостность.

CREATE TABLE users (
  id    bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email text UNIQUE NOT NULL
);

CREATE TABLE orders (
  id      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  total   numeric(12,2) NOT NULL CHECK (total >= 0)
);

CREATE INDEX idx_orders_user_id ON orders (user_id);

FK не строит индекс на ссылающемся столбце автоматически. Без него каскадные удаления и JOIN будут медленными.

4. Базовые операции с данными

SELECT, фильтрация, NULL, сортировка, алиасы.

Откуда ещё можно SELECT

Не только таблицы: VALUES, generate_series, set-returning функции, подзапросы.

SELECT * FROM (VALUES (1,'a'),(2,'b')) AS v(id, name);

SELECT generate_series('2026-01-01'::date,
                       '2026-12-01'::date,
                       interval '1 month') AS month;

SELECT * FROM regexp_split_to_table('a,b,c', ',') AS t(part);

Булева алгебра в SQL

Логика трёхзначная: TRUE / FALSE / NULL. WHERE отбирает только TRUE.

SELECT TRUE  AND NULL;   -- NULL
SELECT TRUE  OR  NULL;   -- TRUE
SELECT FALSE AND NULL;   -- FALSE
SELECT NULL = NULL;      -- NULL  (а не TRUE!)

-- неприятный сюрприз:
SELECT * FROM t WHERE x NOT IN (1, 2, NULL);   -- никогда ничего не вернёт

NULL и coalesce

NULL — «неизвестно». coalesce / NULLIF — основной инструмент работы с ним.

SELECT coalesce(nickname, full_name, 'аноним') AS display_name
FROM   users;

SELECT a / NULLIF(b, 0) AS ratio FROM t;

SELECT count(*)        AS rows_total,
       count(email)    AS with_email,
       sum(amount)     AS total_amount   -- агрегаты игнорируют NULL
FROM   orders;

Сортировка: ORDER BY

ASC/DESC, NULLS FIRST/LAST, по нескольким столбцам и выражениям.

SELECT id, email, deleted_at
FROM   users
ORDER  BY deleted_at DESC NULLS LAST,
          email      ASC;

SELECT *
FROM   events
ORDER  BY (data->>'priority')::int DESC, ts;

NULL по умолчанию идёт «больше» при ASC и «меньше» при DESC. Если нужно иначе — пиши NULLS FIRST или NULLS LAST явно.

Псевдонимы (aliases)

AS для столбцов и таблиц делает запросы короче.

SELECT u.id     AS user_id,
       u.email,
       o.id     AS order_id,
       o.total
FROM   users  u
JOIN   orders o ON o.user_id = u.id;

Псевдоним столбца виден в ORDER BY, но не в WHERE/GROUP BY: они логически вычисляются раньше, чем SELECT назначает имена.

5. Реляционные vs нереляционные

Реляционные vs нереляционные СУБД

Когда брать Postgres, а когда — Mongo, Redis, Cassandra.

Реляционная СУБД даёт сильную согласованность, схему и язык запросов. Нереляционные жертвуют чем-то из этого ради скорости, гибкости схемы или горизонтального масштаба. Postgres сильно «отъедает» у документных хранилищ за счёт jsonb и расширений.

6. Последовательности

SEQUENCE — генератор номеров

Стоит за serial и identity. Иногда полезен сам по себе.

CREATE SEQUENCE order_no_seq START 1000 INCREMENT 1;

SELECT nextval('order_no_seq');   -- получить следующее значение
SELECT currval('order_no_seq');   -- последнее в этой сессии
SELECT setval ('order_no_seq', 1000, false);  -- сбросить
ALTER  SEQUENCE order_no_seq RESTART WITH 1;

nextval работает вне транзакции — отменённый ROLLBACK не возвращает выданный номер. В номерах будут «дыры» — это нормально.

7. Анатомия кластера

Кластер → БД → схема → tablespace → файл → страница

Физическая раскладка данных Postgres на диске.

SHOW data_directory;
SELECT current_setting('block_size');   -- обычно 8192 (8 КБ)

SELECT spcname, pg_tablespace_location(oid)
FROM   pg_tablespace;

-- Размер каждой БД:
SELECT datname, pg_size_pretty(pg_database_size(datname))
FROM   pg_database
ORDER  BY pg_database_size(datname) DESC;

Страница (page) — единица чтения/записи. Большие значения автоматически уезжают в TOAST, но это прозрачно для пользователя.

Упражнения

Используется учебный датасет (см. раздел «Учебный датасет»). Напиши свой запрос в textarea, потом сравни с эталоном или разбери с ИИ-ментором — он не покажет ответ сразу, а пройдётся по логике.

1. Активные пользователи, отсортированные по дате

Из таблицы users выведи id, email, created_at для всех пользователей, у которых is_active = true и deleted_at IS NULL. Отсортируй по дате регистрации, более свежие — сверху.

SELECT id, email, created_at
FROM   users
WHERE  is_active = true
  AND  deleted_at IS NULL
ORDER  BY created_at DESC;

Условие deleted_at IS NULL нельзя писать как deleted_at = NULL: сравнение с NULL всегда даёт NULL, а WHERE отбирает только TRUE.

2. COALESCE для отображаемого имени

Из users выведи id и одно поле display_name. Логика: если есть nickname — берём его; иначе full_name; иначе строку 'аноним'. Только активные пользователи (is_active = true).

SELECT id,
       coalesce(nickname, full_name, 'аноним') AS display_name
FROM   users
WHERE  is_active = true
ORDER  BY id;

coalesce возвращает первый аргумент, не равный NULL. Часто используется для дефолтов на стороне SQL.

3. Считаем активных одним запросом

Одним запросом получи две колонки: total — общее число строк в users, active — число тех, у кого is_active = true и deleted_at IS NULL.

SELECT count(*)                                              AS total,
       count(*) FILTER (WHERE is_active AND deleted_at IS NULL) AS active
FROM   users;

FILTER (WHERE …) — стандартный способ условной агрегации в PostgreSQL. Альтернатива: sum(CASE WHEN … THEN 1 ELSE 0 END).

Мини-тест по основам

  1. Что вернёт запрос SELECT NULL = NULL;?

    NULL означает «неизвестно». Сравнение неизвестного с неизвестным — тоже неизвестно. Используй IS NULL / IS NOT NULL.

  2. Какая категория SQL у команды GRANT SELECT ON t TO readonly;?

    DCL (Data Control Language) — это GRANT и REVOKE.

  3. В Postgres команды на бэкслеше (\dt, \c) — это…

    Это команды клиента psql; на стороне сервера их не существует.

  4. Какой результат у SELECT coalesce(NULL, NULL, 'аноним');?

    coalesce возвращает первый аргумент, не равный NULL. Если все NULL — последний (NULL). Здесь последний — строка.

  5. В каком порядке логически вычисляются части SELECT?

    Логически: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. Поэтому алиасы из SELECT доступны в ORDER BY, но не в WHERE.
