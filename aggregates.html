PostgreSQL · Агрегации

Агрегации, CASE, DISTINCT, подзапросы и set-операции

Всё, что превращает «много строк» в «один ответ»: агрегатные функции, фильтры и группировки, борьба с N+1 через json_agg, ROLLUP/CUBE, подзапросы и UNION/EXCEPT/INTERSECT.

1. Агрегатные функции

count, sum, avg, min, max, string_agg, array_agg

Стандартный набор плюс агрегаты-сборщики и FILTER для условий.

SELECT count(*)                 AS rows_total,
       count(email)             AS with_email,
       count(DISTINCT user_id)  AS uniq_users,
       sum(amount)              AS total,
       avg(amount)              AS avg_amount,
       min(created_at)          AS first_seen,
       max(created_at)          AS last_seen,
       count(*) FILTER (WHERE status = 'paid')   AS paid_count,
       count(*) FILTER (WHERE status = 'cancel') AS cancelled_count,
       string_agg(email, ', ' ORDER BY email)    AS email_list,
       array_agg(id ORDER BY id)                 AS ids
FROM   orders;

count(*) считает строки, count(col) — только не-NULL значения. FILTER идиоматичнее CASE WHEN ... ELSE NULL END внутри агрегата.

2. JSON_AGG vs ORM

Агрегация в JSON: один запрос вместо N+1

Часто типичная «простыня» N+1 в ORM лечится одним SQL.

-- было в коде: для каждого пользователя — отдельный запрос за заказами.
-- стало: один SQL, JSON-массив заказов уже в ответе.

SELECT u.id,
       u.email,
       coalesce(
         json_agg(
           json_build_object(
             'id',         o.id,
             'total',      o.total,
             'created_at', o.created_at
           )
           ORDER BY o.created_at DESC
         ) FILTER (WHERE o.id IS NOT NULL),
         '[]'::json
       ) AS orders
FROM   users u
LEFT JOIN orders o ON o.user_id = u.id
GROUP  BY u.id, u.email
ORDER  BY u.id;

FILTER (WHERE o.id IS NOT NULL) важна: без неё пользователь без заказов получит массив [null] вместо [].

3. CASE WHEN

Условные выражения

«Если X, то Y; иначе Z». Работает везде, где можно писать выражение.

SELECT id, total,
       CASE
         WHEN total = 0      THEN 'free'
         WHEN total < 1000   THEN 'small'
         WHEN total < 10000  THEN 'medium'
         ELSE                     'big'
       END AS bucket
FROM   orders;

-- альтернативная форма (когда сравниваем с одним выражением):
SELECT id,
       CASE status
         WHEN 'new'    THEN 1
         WHEN 'paid'   THEN 2
         WHEN 'cancel' THEN 99
       END AS status_order
FROM   orders;

Без ELSE для непокрытых случаев возвращается NULL. Для условных агрегатов чаще читабельнее FILTER (WHERE ...), чем sum(CASE WHEN ... THEN 1 ELSE 0 END).

4. Группировка и фильтрация

HAVING — фильтр после агрегации

WHERE отбирает строки до GROUP BY, HAVING — после.

SELECT user_id,
       count(*)   AS orders_total,
       sum(total) AS revenue
FROM   orders
WHERE  created_at >= now() - interval '90 days'   -- до агрегации
GROUP  BY user_id
HAVING count(*) > 5                                -- после агрегации
   AND sum(total) > 10000
ORDER  BY revenue DESC;

В HAVING разрешены агрегаты, в WHERE — нет. Если условие можно записать без агрегата — пиши его в WHERE: дешевле и часто использует индекс.

DISTINCT и DISTINCT ON

Убирает дубли по всем столбцам или по подмножеству — Postgres-специфика.

-- DISTINCT: уникальные комбинации всех выбранных столбцов:
SELECT DISTINCT country FROM customers;
SELECT DISTINCT country, gender FROM customers;

-- DISTINCT ON: первая строка для каждого user_id по порядку:
SELECT DISTINCT ON (user_id)
       user_id, id, created_at, total
FROM   orders
ORDER  BY user_id, created_at DESC;

DISTINCT ON (...) требует, чтобы ORDER BY начинался с тех же столбцов. Часто DISTINCT в коде — это «костыль» поверх неправильного JOIN; перед тем как добавить, проверь, нет ли лишнего соединения.

GROUPING SETS, ROLLUP, CUBE

Несколько уровней группировки в одном запросе.

-- ROLLUP — иерархия с подытогами:
SELECT country, city, count(*) AS n
FROM   customers
GROUP  BY ROLLUP (country, city)
ORDER  BY country NULLS LAST, city NULLS LAST;

-- CUBE — все возможные комбинации:
SELECT country, gender, count(*) AS n
FROM   customers
GROUP  BY CUBE (country, gender);

-- GROUPING SETS — точный список:
SELECT country, gender, count(*) AS n
FROM   customers
GROUP  BY GROUPING SETS ((country), (gender), ());

Строки с подытогами отличаются NULL в столбце группировки. Для надёжного отличения «настоящего» NULL от «итог по этому столбцу» используют функцию grouping(col).

5. Подзапросы

Скалярные, табличные, коррелированные

Три формы — три разных смысла.

-- 1. Скалярный (один столбец, одна строка):
SELECT u.id,
       u.email,
       (SELECT count(*) FROM orders o WHERE o.user_id = u.id) AS orders_total
FROM   users u;

-- 2. Табличный (в FROM):
SELECT *
FROM   (
  SELECT user_id, count(*) AS c
  FROM   orders
  GROUP  BY user_id
) t
WHERE  t.c > 10;

-- 3. С ANY / ALL:
SELECT *
FROM   products
WHERE  price > ALL (SELECT price FROM products WHERE category = 'budget');

-- 4. EXISTS (см. также semi-join на странице соединений):
SELECT * FROM users u
WHERE  EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

Скалярный подзапрос обязан возвращать ровно одну строку и один столбец. Если запрос становится тяжёлым — часто его лучше переписать через JOIN или WITH.

6. UNION, EXCEPT, INTERSECT

Операции над множествами

Объединение, вычитание и пересечение результатов запросов.

-- объединение, без дублей (дороже — внутри сортировка):
SELECT id FROM new_users
UNION
SELECT id FROM trial_users;

-- объединение, с дублями (быстрее, по умолчанию выбирай это):
SELECT id FROM new_users
UNION ALL
SELECT id FROM trial_users;

-- разница: пользователи активные, но не платящие:
SELECT id FROM active_users
EXCEPT
SELECT id FROM paying_users;

-- пересечение:
SELECT id FROM active_users
INTERSECT
SELECT id FROM paying_users;

Количество и типы столбцов должны совпадать. ORDER BY ставится в самом конце — он сортирует объединённый результат, а не отдельные части.
