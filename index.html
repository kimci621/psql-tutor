Шпаргалка по PostgreSQL

Краткая выжимка команд и приёмов с примерами и пояснениями на русском. У каждой темы есть кнопка «Поучиться с ИИ» — она открывает диалог с локальным наставником (LM Studio): сначала он объясняет выбранную тему с примерами, затем проверяет понимание и помогает разобраться через вопросы.

1. Подключение и сессия

Запуск psql, выбор БД, информация о текущем окружении.

Подключение через psql

Утилита psql подключается к серверу с указанием хоста, порта, пользователя и БД.

psql -h localhost -p 5432 -U postgres -d mydb
\c another_db

Параметры: -h хост, -p порт, -U пользователь, -d имя БД. Команда \c внутри psql переключает БД без перезапуска утилиты.

Информация о сессии

Версия сервера, текущий пользователь и БД, активный search_path.

SELECT version();
SELECT current_user, current_database();
SHOW search_path;

search_path определяет порядок схем, в которых ищутся неквалифицированные имена объектов. current_user и session_user могут отличаться после SET ROLE.

2. Базы данных

Создание, удаление, просмотр и измерение размеров.

Создание базы

Создавай БД с явной кодировкой, владельцем и шаблоном.

CREATE DATABASE shop
  OWNER     app_user
  ENCODING  'UTF8'
  TEMPLATE  template0;

template0 — «чистый» шаблон без локаль-зависимых объектов; удобен, когда задаёшь нестандартную кодировку.

Удаление базы

Сначала освободи БД от подключений, затем удаляй.

SELECT pg_terminate_backend(pid)
FROM   pg_stat_activity
WHERE  datname = 'shop'
  AND  pid <> pg_backend_pid();

DROP DATABASE IF EXISTS shop;

В PostgreSQL 13+ работает DROP DATABASE shop WITH (FORCE); — он сам отключит клиентов.

Список баз и их размер

Через psql и через системный каталог.

\l

SELECT datname,
       pg_size_pretty(pg_database_size(datname)) AS size
FROM   pg_database
ORDER  BY pg_database_size(datname) DESC;

3. Схемы

Пространства имён внутри одной БД.

Создание схемы

Группируй объекты по логическим зонам и управляй search_path.

CREATE SCHEMA IF NOT EXISTS reporting AUTHORIZATION analyst;
SET search_path = reporting, public;

Список схем

Метакоманда psql и запрос к information_schema.

\dn

SELECT schema_name
FROM   information_schema.schemata
ORDER  BY schema_name;

4. Таблицы (DDL)

Создание, изменение и удаление таблиц.

CREATE TABLE — базовый синтаксис

Опиши столбцы, типы, ограничения и значения по умолчанию.

CREATE TABLE users (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email      text UNIQUE NOT NULL,
  is_active  boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now()
);

С PG 10+ предпочитай GENERATED ALWAYS AS IDENTITY вместо bigserial: явный стандарт SQL и аккуратные права.

ALTER TABLE

Добавление, удаление и переименование столбцов и ограничений.

ALTER TABLE users ADD    COLUMN last_login timestamptz;
ALTER TABLE users DROP   COLUMN last_login;
ALTER TABLE users RENAME COLUMN email TO email_address;
ALTER TABLE users ALTER  COLUMN is_active SET DEFAULT false;

DROP и TRUNCATE

Удаление таблицы целиком и быстрая очистка содержимого.

DROP TABLE IF EXISTS old_users CASCADE;

TRUNCATE users RESTART IDENTITY CASCADE;

TRUNCATE минует триггеры ON DELETE и обычно гораздо быстрее, чем массовый DELETE, но забирает ACCESS EXCLUSIVE.

5. Типы данных

Базовый набор и типичные ловушки.

Числа, строки, время, jsonb, массивы

Большая часть прикладных задач закрывается этими типами.

CREATE TABLE t (
  i   integer,
  bi  bigint,
  n   numeric(12,2),
  s   text,
  v   varchar(255),
  ts  timestamptz,
  u   uuid,
  j   jsonb,
  arr int[]
);

numeric — точная арифметика; real/double precision — приблизительная. Длина в varchar(n) не даёт выигрыша по хранению.

6. Ограничения целостности

PRIMARY KEY, UNIQUE, FOREIGN KEY, CHECK и DEFAULT.

Сводный пример

Все базовые ограничения в одной таблице.

CREATE TABLE orders (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id    bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  total      numeric(12,2) NOT NULL CHECK (total >= 0),
  status     text NOT NULL DEFAULT 'new',
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (user_id, created_at)
);

7. CRUD

INSERT / UPDATE / DELETE и UPSERT.

INSERT и RETURNING

Одиночные и пакетные вставки, возврат сгенерированных значений.

INSERT INTO users (email)
VALUES  ('a@example.com'), ('b@example.com')
RETURNING id, email;

UPSERT через ON CONFLICT

Атомарная вставка-или-обновление по UNIQUE.

INSERT INTO counters (key, n)
VALUES  ('hits', 1)
ON CONFLICT (key) DO UPDATE
  SET n = counters.n + EXCLUDED.n
RETURNING n;

UPDATE и DELETE с условиями из других таблиц

FROM в UPDATE и USING в DELETE.

UPDATE orders o
SET    status = 'paid'
FROM   payments p
WHERE  p.order_id = o.id
  AND  p.success;

DELETE FROM sessions
WHERE  expires_at < now()
RETURNING id;

8. Выборка (SELECT)

Базовые операторы и пагинация.

SELECT с WHERE, ORDER BY, LIMIT

Минимальный набор для повседневных запросов.

SELECT id, email
FROM   users
WHERE  is_active
ORDER  BY created_at DESC
LIMIT  10;

Фильтрация: IN, BETWEEN, LIKE, IS NULL

Главная ловушка — поведение NULL в сравнениях.

SELECT * FROM products WHERE price BETWEEN 100 AND 500;
SELECT * FROM orders   WHERE status IN ('new','paid');
SELECT * FROM users    WHERE email LIKE '%@example.com';
SELECT * FROM users    WHERE deleted_at IS NULL;

Пагинация: OFFSET и keyset

OFFSET читаемый, но дорогой; keyset — быстрый.

-- классическая, удобная, но медленная на больших таблицах:
SELECT * FROM posts ORDER BY created_at DESC LIMIT 20 OFFSET 100;

-- keyset-пагинация:
SELECT * FROM posts
WHERE  created_at < $1
ORDER  BY created_at DESC
LIMIT  20;

9. Соединения

INNER, LEFT, FULL, CROSS и LATERAL.

Базовые JOIN

Разные типы соединений с одинаковыми таблицами.

SELECT u.email, o.id
FROM   users u
JOIN   orders o ON o.user_id = u.id;

SELECT u.email, o.id
FROM   users u
LEFT JOIN orders o ON o.user_id = u.id;

Условие на «правую» таблицу в WHERE после LEFT JOIN неявно превращает его в INNER. Если хочешь сохранить семантику — фильтруй внутри ON.

LATERAL JOIN: «top-N на пользователя»

Подзапрос видит столбцы предыдущих таблиц.

SELECT u.id, latest.created_at
FROM   users u
LEFT JOIN LATERAL (
  SELECT created_at FROM orders o
  WHERE  o.user_id = u.id
  ORDER  BY created_at DESC
  LIMIT  1
) latest ON true;

10. Агрегации

GROUP BY, HAVING, FILTER.

GROUP BY с FILTER

Условные агрегаты без CASE WHEN.

SELECT user_id,
       count(*) FILTER (WHERE status = 'paid') AS paid_count,
       count(*)                                AS all_count,
       sum(total)                              AS revenue
FROM   orders
GROUP  BY user_id
HAVING count(*) > 5
ORDER  BY revenue DESC;

11. CTE и подзапросы

WITH и рекурсия.

WITH — именованные подзапросы

Делает запрос читаемым, можно ссылаться несколько раз.

WITH active AS (
  SELECT id, email FROM users WHERE is_active
)
SELECT a.email, count(o.id)
FROM   active a
LEFT JOIN orders o ON o.user_id = a.id
GROUP  BY a.email;

WITH RECURSIVE — обход иерархий

Деревья категорий, графы зависимостей.

WITH RECURSIVE tree AS (
  SELECT id, parent_id, 1 AS depth FROM categories WHERE parent_id IS NULL
  UNION ALL
  SELECT c.id, c.parent_id, t.depth + 1
  FROM   categories c
  JOIN   tree t ON c.parent_id = t.id
)
SELECT * FROM tree;

12. Оконные функции

Аналитика без потери исходных строк.

ROW_NUMBER, LAG, PARTITION BY

«N последних на пользователя» и разности по соседним строкам.

SELECT user_id, id, created_at,
       row_number() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
FROM   orders;

SELECT id, total,
       total - lag(total) OVER (ORDER BY id) AS diff
FROM   orders;

13. Индексы

B-tree, частичные, по выражению, GIN.

CREATE INDEX (B-tree)

Базовый индекс по столбцу или выражению.

CREATE INDEX CONCURRENTLY idx_orders_user_created
  ON orders (user_id, created_at DESC);

CREATE INDEX idx_users_email_lower
  ON users (lower(email));

Частичный индекс

Покрывает только часть строк по предикату.

CREATE INDEX idx_orders_active
  ON orders (user_id)
  WHERE status <> 'cancelled';

GIN для jsonb и массивов

Индексы по составным значениям.

CREATE INDEX idx_docs_data ON docs USING gin (data);
CREATE INDEX idx_docs_tags ON docs USING gin (tags);

14. Транзакции и блокировки

Уровни изоляции и FOR UPDATE.

BEGIN/COMMIT и уровни изоляции

По умолчанию READ COMMITTED; SERIALIZABLE требует retry.

BEGIN ISOLATION LEVEL SERIALIZABLE;
  UPDATE accounts SET balance = balance - 100 WHERE id = 1;
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;

FOR UPDATE SKIP LOCKED — очередь задач

Шаблон для неблокирующей обработки заданий.

BEGIN;
  SELECT * FROM jobs
  WHERE  status = 'pending'
  ORDER  BY id
  LIMIT  1
  FOR UPDATE SKIP LOCKED;

  UPDATE jobs SET status = 'done' WHERE id = $1;
COMMIT;

15. Представления

VIEW и MATERIALIZED VIEW.

VIEW — виртуальная таблица

Сохранённый запрос, выполняется при каждом обращении.

CREATE OR REPLACE VIEW active_users AS
SELECT id, email FROM users WHERE is_active;

MATERIALIZED VIEW и REFRESH

Кэш результатов запроса с явным обновлением.

CREATE MATERIALIZED VIEW daily_stats AS
SELECT date_trunc('day', created_at) AS d, count(*)
FROM   orders
GROUP  BY 1;

REFRESH MATERIALIZED VIEW CONCURRENTLY daily_stats;

16. Роли и права

CREATE ROLE и GRANT.

CREATE ROLE

Сервисная роль и роль-«группа».

CREATE ROLE app_user LOGIN PASSWORD 'secret';
CREATE ROLE readonly NOLOGIN;
GRANT  readonly TO app_user;

GRANT, REVOKE и DEFAULT PRIVILEGES

Права на схемы и таблицы, в том числе на будущие.

GRANT USAGE  ON SCHEMA public TO readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT ON TABLES TO readonly;

17. Обслуживание

VACUUM, ANALYZE, REINDEX.

VACUUM

Уборка мёртвых версий строк и обновление статистики.

VACUUM (VERBOSE, ANALYZE) orders;
-- Жёсткая уборка с переписыванием таблицы (блокировка ACCESS EXCLUSIVE):
VACUUM FULL orders;

ANALYZE — статистика для планировщика

Свежая статистика — хороший план запроса.

ANALYZE users;
ANALYZE VERBOSE;

REINDEX CONCURRENTLY

Перестройка раздутого индекса без даунтайма.

REINDEX INDEX CONCURRENTLY idx_orders_user_created;
REINDEX TABLE CONCURRENTLY orders;

18. EXPLAIN

План запроса и фактические тайминги.

EXPLAIN (ANALYZE, BUFFERS)

Сравни предсказание и факт; смотри узкие места.

EXPLAIN SELECT * FROM orders WHERE user_id = 1;

EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM orders WHERE user_id = 1;

EXPLAIN ANALYZE реально выполняет запрос. Для UPDATE/DELETE оборачивай в транзакцию с откатом.

19. JSON / JSONB

Гибкие данные и индексы по ним.

Доступ и поиск в jsonb

->, ->>, @> и GIN-индекс.

SELECT data->>'name' AS name FROM docs;
SELECT *            FROM docs WHERE data @> '{"role":"admin"}';
SELECT jsonb_array_elements(data->'tags') FROM docs;

20. Дата и время

now(), interval, date_trunc, часовые пояса.

Группировка по дням и сдвиг таймзоны

date_trunc и AT TIME ZONE.

SELECT now(), now() - interval '7 days';

SELECT date_trunc('day', created_at) AS d, count(*)
FROM   orders
GROUP  BY 1;

SELECT now() AT TIME ZONE 'Europe/Moscow';
