Полнотекстовый и fuzzy поиск

Когда LIKE '%foo%' уже не справляется, у Postgres есть две встроенные опции, достаточно мощные, чтобы во многих проектах заменить Elasticsearch. Полнотекстовый поиск (tsvector + GIN-индекс) ищет по словам и словоформам, pg_trgm — по подстрокам и похожести.

Полнотекстовый поиск

Структурированная индексация по словам и нормализации. Подходит для статей, описаний, документов.

Полнотекстовый поиск

tsvector, tsquery, GIN-индекс.

ALTER TABLE articles ADD COLUMN tsv tsvector
  GENERATED ALWAYS AS (
    to_tsvector('russian', coalesce(title,'') || ' ' || coalesce(body,''))
  ) STORED;

CREATE INDEX idx_articles_tsv ON articles USING gin (tsv);

SELECT id, ts_rank(tsv, q) AS rank
FROM   articles, plainto_tsquery('russian', $1) q
WHERE  tsv @@ q
ORDER  BY rank DESC
LIMIT  20;

Нечёткий поиск через pg_trgm

Когда нужно «найти похожее», искать опечатки, или просто ускорить ILIKE '%…%' — это сюда.

pg_trgm — нечёткий и подстрочный поиск

Ускоряет LIKE '%foo%' и даёт similarity().

CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE INDEX idx_users_email_trgm
  ON users USING gin (email gin_trgm_ops);

SELECT * FROM users WHERE email ILIKE '%example%';

SELECT *, similarity(name, $1) AS s
FROM   users
ORDER  BY s DESC
LIMIT  10;
