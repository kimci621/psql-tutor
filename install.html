Установка PostgreSQL

Четыре способа поднять Postgres: пакетный менеджер ОС (для прода и обычной разработки), Docker (для одноразовых тестов и сред), сборка из исходников (для тех, кто пишет расширения), managed-облако (когда не хочется заниматься эксплуатацией).

1. Какой способ выбрать

Варианты установки

Сравнение четырёх путей: что проще, что надёжнее, что быстрее.

СпособКогда братьМинусы
Пакетный менеджер (apt/dnf/brew)Локальная разработка, прод на bare-metal/VMВерсия из дистрибутива часто устарела — нужен pgdg-репозиторий
DockerБыстрый старт, изолированные тесты, CIВ проде нужны Patroni/StackGres, не «голый» docker
Из исходниковРазработка ядра/расширений, нестандартные опцииДолго, требует разбора зависимостей
Managed (RDS/Yandex Cloud/Supabase)Когда нет команды DBAДороже, ограничения по расширениям и доступу

2. Через пакетный менеджер

Установка из пакетного менеджера

Для Ubuntu/Debian — официальный pgdg-репозиторий. Версия всегда актуальная.

# Ubuntu/Debian — pgdg-репозиторий:
sudo install -d /usr/share/postgresql-common/pgdg
sudo apt-get install -y curl ca-certificates lsb-release
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc \
  https://www.postgresql.org/media/keys/ACCC4CF8.asc
sudo sh -c 'echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" \
  > /etc/apt/sources.list.d/pgdg.list'

sudo apt-get update
sudo apt-get install -y postgresql-16

# Проверка:
sudo systemctl status postgresql
sudo -u postgres psql -c "SELECT version();"

На macOS — brew install postgresql@16 && brew services start postgresql@16. На RHEL/Fedora — dnf module enable postgresql:16 && dnf install postgresql-server, затем postgresql-setup --initdb.

3. В контейнере

Установка в Docker

Один контейнер, том для данных, готово.

docker run --name pg \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=app \
  -e POSTGRES_USER=app \
  -p 5432:5432 \
  -v pg-data:/var/lib/postgresql/data \
  -d postgres:16

docker exec -it pg psql -U app -d app

# С docker-compose это выглядит так:
# services:
#   db:
#     image: postgres:16
#     environment:
#       POSTGRES_PASSWORD: secret
#     volumes:
#       - pg-data:/var/lib/postgresql/data
#     ports: ["5432:5432"]
# volumes: { pg-data: {} }

Без флага -v данные исчезнут при удалении контейнера. POSTGRES_PASSWORD обязателен — без него образ не стартует. Для прода один контейнер не годится: нужен Patroni / StackGres / managed-сервис.

4. Из исходников

Сборка PostgreSQL из исходников

Когда нужны патчи, нестандартный --prefix или работа над ядром.

wget https://ftp.postgresql.org/pub/source/v16.0/postgresql-16.0.tar.gz
tar xf postgresql-16.0.tar.gz
cd postgresql-16.0

./configure --prefix=/opt/pg16 \
            --with-openssl \
            --with-icu \
            --with-libxml
make -j"$(nproc)"
sudo make install

# Инициализация каталога данных:
sudo mkdir -p /opt/pg16/data
sudo chown $USER /opt/pg16/data
/opt/pg16/bin/initdb -D /opt/pg16/data --locale=en_US.UTF-8 -E UTF8

# Запуск:
/opt/pg16/bin/pg_ctl -D /opt/pg16/data -l /opt/pg16/data/server.log start
/opt/pg16/bin/psql -h /tmp -d postgres

initdb создаёт системные каталоги и пустой кластер. Без --with-openssl не будет TLS, без --with-icu — современных коллаций. Для приклада ставь из пакетов; «исходники» — путь разработчика расширений.
