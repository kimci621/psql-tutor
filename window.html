Оконные функции (window functions)

То, что обычная агрегация не умеет: считать что-то «по группе», но при этом не схлопывать строки. Здесь и running totals, и top-N per group, и dedupe — всё на одной странице, на учебном датасете.

1. Что такое окно

OVER (...) — окно для каждой строки

Агрегат + OVER = считаем по группе, но возвращаем строки.

-- сумма всех заказов рядом с каждым заказом:
SELECT id, user_id, total,
       sum(total) OVER () AS total_overall
FROM   orders;

-- та же сумма, но отдельно для каждого пользователя:
SELECT id, user_id, total,
       sum(total) OVER (PARTITION BY user_id) AS total_user
FROM   orders;

Окно — это набор строк, на котором функция работает для текущей строки. Без OVER агрегат схлопывает группу, с OVER — нет.

PARTITION BY разбивает на группы. ORDER BY внутри окна задаёт порядок, по которому считается running aggregate (см. ниже).

2. Frames: ROWS / RANGE / GROUPS

Кадр окна — что включается в расчёт

Без явного frame по умолчанию — RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW (если есть ORDER BY) или вся партиция (если нет).

-- ROWS: считает по физическим строкам
SELECT id, total,
       sum(total) OVER (
         ORDER BY id
         ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
       ) AS rolling_3
FROM   orders;

-- RANGE: считает по значению ORDER BY (ловит дубли вместе)
SELECT created_at::date AS day, total,
       sum(total) OVER (
         ORDER BY created_at::date
         RANGE BETWEEN INTERVAL '7 days' PRECEDING AND CURRENT ROW
       ) AS sum_last_7d
FROM   orders;

-- GROUPS (PG 11+): кадр в «пачках» одинаковых ORDER BY значений
SELECT user_id, created_at::date, total,
       sum(total) OVER (
         PARTITION BY user_id
         ORDER BY created_at::date
         GROUPS BETWEEN 1 PRECEDING AND CURRENT ROW
       ) AS sum_today_and_yesterday
FROM   orders;
  • ROWS — по строкам после сортировки. «Последние N строк».
  • RANGE — по значению. Все строки с тем же ключом ORDER BY попадают в кадр вместе.
  • GROUPS — по группам одинаковых ORDER BY значений (PG 11+).
  • PRECEDING, FOLLOWING, CURRENT ROW, UNBOUNDED PRECEDING/FOLLOWING — границы кадра.
  • Дефолтный кадр в большинстве случаев работает «не как ожидаешь» — задавай явно.

3. LAG, LEAD, FIRST_VALUE, LAST_VALUE

LAG / LEAD — соседние строки

Заглянуть на N строк назад/вперёд внутри окна.

-- разница между текущей и предыдущей суммой по пользователю:
SELECT user_id, id, total,
       lag(total) OVER (PARTITION BY user_id ORDER BY created_at) AS prev_total,
       total - lag(total) OVER (PARTITION BY user_id ORDER BY created_at) AS delta
FROM   orders;

-- следующий заказ:
SELECT id, user_id, created_at,
       lead(created_at) OVER (PARTITION BY user_id ORDER BY created_at) AS next_order_at
FROM   orders;

-- LAG с дефолтом, чтобы не было NULL:
lag(total, 1, 0) OVER (...);

FIRST_VALUE / LAST_VALUE / NTH_VALUE

Первая, последняя или N-я строка кадра — берегись дефолтного frame для LAST_VALUE.

-- первая покупка пользователя рядом с каждой:
SELECT user_id, id, created_at,
       first_value(id) OVER (
         PARTITION BY user_id ORDER BY created_at
         ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
       ) AS first_order_id
FROM   orders;

-- частая ошибка с LAST_VALUE:
SELECT user_id, id,
       last_value(id) OVER (PARTITION BY user_id ORDER BY created_at) AS last_id
FROM   orders;
-- ↑ возвращает текущий id, а не последний — потому что дефолтный frame
--   = RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW.
-- Правильно — задать frame явно:
last_value(id) OVER (
  PARTITION BY user_id
  ORDER BY created_at
  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
)

4. Ранжирование

ROW_NUMBER / RANK / DENSE_RANK

Три способа пронумеровать строки внутри окна.

SELECT user_id, id, total,
       row_number() OVER (PARTITION BY user_id ORDER BY total DESC) AS rn,
       rank()       OVER (PARTITION BY user_id ORDER BY total DESC) AS rk,
       dense_rank() OVER (PARTITION BY user_id ORDER BY total DESC) AS drk
FROM   orders;
-- При двух одинаковых total:
--   row_number: 1, 2, 3, 4    (всегда уникален)
--   rank:       1, 2, 2, 4    (пропуски после ничьей)
--   dense_rank: 1, 2, 2, 3    (без пропусков)

Используй row_number(), когда нужна уникальность; dense_rank() — для рейтингов «без дыр»; rank() — для классических спортивных мест.

5. Паттерны

Running totals (нарастающий итог)

Сумма с начала истории до текущей строки.

SELECT id, created_at, total,
       sum(total) OVER (
         ORDER BY created_at
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_total
FROM   orders;

-- Отдельно для каждого пользователя:
SELECT user_id, id, created_at, total,
       sum(total) OVER (
         PARTITION BY user_id
         ORDER BY created_at
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS user_running_total
FROM   orders;

Top-N per group

«Дай мне три самых дорогих заказа на каждого пользователя».

SELECT *
FROM   (
  SELECT user_id, id, total,
         row_number() OVER (
           PARTITION BY user_id
           ORDER BY total DESC
         ) AS rn
  FROM   orders
) AS t
WHERE  rn <= 3;

-- Или более компактно через LATERAL:
SELECT u.email, top.id, top.total
FROM   users u
JOIN   LATERAL (
  SELECT id, total FROM orders o
  WHERE o.user_id = u.id
  ORDER BY total DESC
  LIMIT 3
) top ON true;

Dedupe — оставить «последнюю» строку из дубликатов

Почистить таблицу, оставив по одной строке на ключ.

-- Найти дубли:
SELECT email, count(*)
FROM   users
GROUP  BY email
HAVING count(*) > 1;

-- Оставить только самую свежую запись по email (если случилось дублирование):
WITH ranked AS (
  SELECT id, email,
         row_number() OVER (
           PARTITION BY lower(email)
           ORDER BY created_at DESC, id DESC
         ) AS rn
  FROM   users
)
DELETE FROM users u
USING  ranked r
WHERE  u.id = r.id
  AND  r.rn > 1;

Перед боевым прогоном — обязательно SELECT-вариант с тем же CTE и просмотр глазами. Удаление по window-функции — мощная штука, но необратимая.

Именованные окна (WINDOW)

Один WINDOW — несколько функций над тем же кадром, без копипасты.

SELECT user_id, id, total, created_at,
       sum(total)         OVER w AS running_total,
       row_number()       OVER w AS rn,
       lag(total)         OVER w AS prev_total
FROM   orders
WINDOW w AS (
  PARTITION BY user_id
  ORDER BY created_at
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
);
