PostgreSQL · Типы данных

Типы данных в PostgreSQL

Числа, строки, ENUM, boolean, массивы. JSON/JSONB и работа с датой и временем — на главной странице шпаргалки и в Senior-разделе. Хороший выбор типа закладывает корректность и производительность на годы вперёд.

1. Зачем нужны типы

Зачем нужны типы данных

Тип — это контракт. Он отбраковывает мусор и сообщает планировщику, как хранить и сравнивать значения.

В text можно положить «понедельник» и «13/13/2026». Когда придёт момент посчитать «сколько заказов за прошлый месяц», окажется, что половина строк не парсится. Правильный тип на этапе схемы — самый дешёвый способ предотвратить такие баги.

2. Числа

Числовые типы

smallint / integer / bigint, numeric (точная), real / double precision (с плавающей точкой).

CREATE TABLE money_demo (
  qty       integer        NOT NULL CHECK (qty >= 0),
  price     numeric(12,2)  NOT NULL,   -- точная арифметика
  weight_kg double precision           -- быстрая, но с погрешностью
);

-- классическая ловушка float:
SELECT 0.1::double precision + 0.2::double precision;   -- 0.30000000000000004
SELECT 0.1::numeric          + 0.2::numeric;            -- 0.3

Деньги — всегда numeric(12,2). Целочисленные счётчики — integer или bigint. double precision — для научных вычислений, где погрешность приемлема, и измерений.

3. Строки

Строковые типы

text, varchar(n), char(n), bytea — и почему чаще всего нужен только text.

CREATE TABLE strings_demo (
  body  text,           -- любая длина, без ограничений; рабочая лошадка
  code  varchar(16),    -- ограничение по длине; внутри хранится так же, как text
  fixed char(8),        -- фиксированная длина с дополнением пробелами (почти не нужно)
  raw   bytea           -- произвольные байты
);

SELECT length(body), char_length(body) FROM strings_demo;
SELECT lower(body), upper(body), trim(body) FROM strings_demo;
SELECT body || ' (правка)' FROM strings_demo;

В Postgres varchar(n) не быстрее text: длина проверяется отдельной операцией. char(n) заполняет пробелами до длины — обычно не то, что нужно. Для бинарных данных — bytea, но для крупных файлов лучше внешнее хранилище.

4. ENUM

Перечисления (ENUM)

Строгий список значений, заданный на уровне типа.

CREATE TYPE order_status AS ENUM ('new','paid','shipped','cancelled');

CREATE TABLE orders (
  id     bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  status order_status NOT NULL DEFAULT 'new'
);

-- добавить новое значение можно:
ALTER TYPE order_status ADD VALUE 'returned';
-- порядок определения определяет сравнение
SELECT 'new'::order_status < 'paid'::order_status;   -- TRUE

Удалить значение из ENUM нельзя — только пересоздать тип. Если набор значений динамический, используй обычную таблицу-справочник + FK. ENUM хорош для редко меняющихся, технических наборов.

5. Boolean

boolean

TRUE / FALSE / NULL и удобные литералы.

CREATE TABLE flags (
  user_id   bigint PRIMARY KEY,
  is_active boolean NOT NULL DEFAULT true
);

-- читать стоит без = TRUE — короче и идиоматичнее:
SELECT * FROM flags WHERE     is_active;
SELECT * FROM flags WHERE NOT is_active;

-- Postgres принимает много вариантов литералов:
SELECT 'yes'::boolean, 't'::boolean, 1::boolean, 'no'::boolean;

Помни про трёхзначную логику: WHERE is_active отбирает только TRUE; строки с NULL отбрасываются. Если важно тоже — пиши WHERE coalesce(is_active, false) или IS NOT FALSE.

6. Массивы

Массивы

Массив любой размерности из любого типа. Удобно — но нормализация часто лучше.

CREATE TABLE posts (
  id   bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  tags text[] NOT NULL DEFAULT '{}'
);

INSERT INTO posts (tags) VALUES
  (ARRAY['sql','postgres']),
  ('{python,db}');                       -- литерал тоже работает

SELECT * FROM posts WHERE 'sql' = ANY (tags);
SELECT * FROM posts WHERE tags @> ARRAY['sql','postgres'];   -- содержит все
SELECT id, unnest(tags) AS tag FROM posts;                   -- развернуть

-- индекс для @> и ANY:
CREATE INDEX idx_posts_tags ON posts USING gin (tags);

Массивы хороши для коротких атрибутов вроде тегов. Если в массиве сотни значений, по которым ходят сложные условия — это сигнал нормализовать в отдельную таблицу. Индексы у массива 1-based: tags[1].
