Список пользователей и ролей

В PostgreSQL «пользователь» и «роль» — это одна и та же сущность. Роль с атрибутом LOGIN может подключаться к серверу, без LOGIN — обычно играет роль группы. Поэтому «список пользователей» можно прочитать тремя разными способами, и они показывают чуть разные данные.

1. Через psql

\du показывает имя, атрибуты и членство в других ролях.

\du
\du+      -- с описанием
\du role  -- одну роль

2. Через pg_roles (все роли)

Системное представление с подробными атрибутами.

SELECT rolname,
       rolsuper,
       rolcanlogin,
       rolcreatedb,
       rolcreaterole,
       rolreplication,
       rolconnlimit,
       rolvaliduntil
FROM   pg_roles
ORDER  BY rolname;

3. Через pg_user (только LOGIN-роли)

Представление-помощник: «настоящие пользователи».

SELECT usename, usesuper, usecreatedb
FROM   pg_user
ORDER  BY usename;

Кто в какой роли состоит

Иерархия ролей через pg_auth_members.

SELECT r.rolname  AS role,
       m.rolname  AS member,
       am.admin_option
FROM   pg_auth_members am
JOIN   pg_roles r ON r.oid = am.roleid
JOIN   pg_roles m ON m.oid = am.member
ORDER  BY r.rolname, m.rolname;

На что обращать внимание

  • rolsuper = true — суперпользователь, обходит ограничения. Таких ролей должно быть как можно меньше.
  • rolvaliduntil — дата окончания пароля; стоит проверять для сервисных учёток.
  • pg_user прячет роли без LOGIN. Если ищешь «всё» — используй pg_roles.
  • Старые роли с rolcanlogin = false, к которым никто давно не обращается, стоит периодически чистить через DROP ROLE (после REASSIGN OWNED и DROP OWNED).
