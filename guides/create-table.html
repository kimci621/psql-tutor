Как создать таблицу осознанно

Команда CREATE TABLE кажется простой, но именно здесь закладывается долговечность модели данных. Правильно выбранные типы, ограничения и стратегия первичного ключа избавят тебя от головной боли при росте таблицы.

Минимальный современный шаблон

Identity-ключ, явные NOT NULL и DEFAULT, timestamptz.

CREATE TABLE products (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sku         text   NOT NULL UNIQUE,
  name        text   NOT NULL,
  price_cents integer NOT NULL CHECK (price_cents >= 0),
  is_active   boolean NOT NULL DEFAULT true,
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);

Identity vs serial

Современный способ автоинкремента — стандарт SQL.

-- предпочтительно с PG 10:
id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY

-- старый способ (всё ещё работает):
id bigserial PRIMARY KEY

GENERATED ALWAYS запрещает вставлять явный id извне (нужен OVERRIDING SYSTEM VALUE). Это полезно: убирает класс багов «случайно вставили чужой id».

Внешние ключи

FK с явным правилом каскада и индексом для быстрых соединений.

CREATE TABLE order_items (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  order_id   bigint NOT NULL REFERENCES orders(id)   ON DELETE CASCADE,
  product_id bigint NOT NULL REFERENCES products(id) ON DELETE RESTRICT,
  qty        integer NOT NULL CHECK (qty > 0)
);

CREATE INDEX idx_order_items_order   ON order_items (order_id);
CREATE INDEX idx_order_items_product ON order_items (product_id);

Postgres сам не строит индекс под FK-столбцом. Без индекса JOIN и каскадные удаления могут быть очень медленными.

Generated-столбцы

Хранимое выражение, которое всегда совпадает с правилом.

CREATE TABLE products (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sku         text NOT NULL UNIQUE,
  search_text text GENERATED ALWAYS AS (lower(sku)) STORED
);

CREATE INDEX idx_products_search ON products (search_text);

Удобно для предвычисленного значения, по которому строится индекс — например, lower() для регистронезависимого поиска.

Что часто ломается

  • varchar(n) не даёт выигрыша по производительности; чаще достаточно text.
  • timestamp without time zone ведёт себя неожиданно при смене таймзоны клиента — для прикладных задач предпочитай timestamptz.
  • Ограничения с NOT VALID позволяют добавить FK/CHECK без проверки старых данных, а позже выполнить VALIDATE CONSTRAINT.
  • Если таблица будет очень большой, продумай PARTITION BY заранее — позже секционировать сложнее.
